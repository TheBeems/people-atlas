## Release contract

- Target version: `0.10.0`.
- Tag: exact, unprefixed, annotated `0.10.0`.
- Channel: GitHub prerelease titled `People Atlas 0.10.0 (Alpha)`.

## Scope

1. Change only the declared version authorities to `0.10.0`: `package.json`,
   `manifest.json` and an add-only `versions.json` entry. Do not change
   dependencies or `package-lock.json`.
2. Add accurate English `0.10.0 (Alpha)` changelog and release-note copy. It
   must explain that users should install the successor rather than the
   assetless `0.9.0` prerelease, cover the reviewed contextual actions and
   simplified Settings, retain the fresh-vault boundary, and name exactly the
   three release assets.
3. Commit the complete verified product, evidence and release-preparation
   worktree on `main`, verify remote commit CI, then create and push the
   annotated `0.10.0` tag.
4. Let the existing tag workflow publish and attest the three assets; do not use
   `gh release create` or manually upload assets. After workflow success, set
   the release title and prerelease state with `gh release edit`, then verify
   tag provenance, release metadata, assets, downloaded hashes and attestation.
5. Close this ticket only in a separate docs-only follow-up commit after all
   remote evidence is verified; that closure commit must not move tag `0.10.0`.

## Non-goals

- Rewriting, deleting, force-pushing or otherwise altering the existing public
  `0.9.0` tag or release.
- Product/test/dependency/lockfile/workflow changes beyond the already reviewed
  current worktree and versioned release copy.
- Obsidian Community Plugins submission or manual asset uploads.
- Claiming unperformed live Obsidian Desktop, Bases, pop-out,
  assistive-technology or Mobile validation.
