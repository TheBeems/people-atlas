# Release People Atlas 0.12.0 (Alpha)

## User authorization

On 2026-08-06 the user explicitly asked to **tag and release** the current
main-line worktree. The final feature (`relationship-form-disclosure`, commit
`12078cd`) is the new successor content beyond the already-published 0.11.0
Alpha; it has an independent review PASS (3 rounds) and a green full Node-24
gate. This is therefore a minor successor release, not a rewrite of 0.11.0.

## Release contract

- Target version: `0.12.0`.
- Tag: exact, unprefixed, annotated `0.12.0`.
- Channel: GitHub prerelease titled `People Atlas 0.12.0 (Alpha)`.
- Minimum: Obsidian `1.13.0` remains unchanged.
- Publication owner: the existing tag workflow only; it verifies, attests and
  uploads exactly `main.js`, `manifest.json` and `styles.css`.

## Scope

1. Change only the declared version authorities to `0.12.0`: `package.json`,
   `manifest.json` and an add-only `versions.json` entry. Do not change
   dependencies or `package-lock.json`.
2. Add accurate English `0.12.0 (Alpha)` changelog and release-note copy
   covering the relationship-form sub-grouping (Shortcut/Template disclosures
   + always-visible Core) and noting the continuing fresh-vault-only boundary.
3. Commit the complete verified product, evidence and release-preparation
   worktree on `main`, verify remote CI, then create and push the annotated
   `0.12.0` tag.
4. Let the tag workflow publish and attest the three assets; do not call
   `gh release create` or upload manually. After workflow success, set the
   release title to `People Atlas 0.12.0 (Alpha)` and prerelease state with
   `gh release edit`, then verify tag provenance, release metadata, assets,
   downloaded hashes and attestation.
5. Close this ticket only in a separate docs-only follow-up commit after all
   remote evidence is verified; that closure commit must not move tag `0.12.0`.

## Non-goals

- Rewriting, deleting, force-pushing or otherwise altering any existing public
  tag or release (including `0.11.0`).
- Product/test/dependency/lockfile/workflow changes beyond the already reviewed
  current worktree and the versioned release copy.
- Obsidian Community Plugins submission or manual asset uploads.
- Claiming unperformed live Obsidian Desktop/Bases/pop-out/AT/mobile
  validation.
